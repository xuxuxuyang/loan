# iOS 商城 UI 与下单流程统一设计

## 目标

恢复 iOS、Android 和 H5 共用的商城页面、商品规则与下单体验。iOS 仅在 Apple 审核要求涉及的节点使用独立接口和原生能力，不再维护一套独立商城 UI。

## 不可变约束

- H5 和 Android 的页面结构、商品销售模式、接口地址、请求参数与下单顺序保持不变。
- 先享后付商品只能按原先享后付流程下单，iOS 不提供额外的普通全款购买选项。
- 不修改数据库结构，不执行迁移、回填、批量更新、批量删除或历史数据清理。
- 不修改已经部署的现有 H5、Android 接口契约。
- iOS 审核逻辑只通过 `isIosNativeApp()` 判断，不使用 User-Agent、审核账号、远程开关或 OTA 审核分支。
- 页面只显示正常商城文案，不展示“iOS 独立接口”“风控步骤”“通过前不创建订单”等技术实现说明。
- 保留 Apple 要求的应用内账号注销入口；它是审核合规入口，不改变商城商品和订单业务。
- 本次不执行 `git add`、`git commit`、推送或部署。

## 方案选择

采用“共用原 UI，iOS 守卫注入能力”的方案。四个商城入口恢复渲染现有共用组件，iOS 独立代码只负责注册接口、下单前资料弹卡、iOS 先享后付接口、合同前通讯录上传和账号注销。

不采用复制 H5 页面到 iOS 目录的方案，避免以后两套页面再次漂移；也不进行全面的展示层重构，避免扩大线上 H5 和 Android 的回归范围。

## 页面与组件设计

### 注册

`MallRegisterView.vue` 只渲染现有 `RegisterForm.vue`。`RegisterForm.vue` 保持原页面标题、卡片、输入框、协议和按钮样式，通过 `isIosNativeApp()` 控制字段与接口：

- iOS 显示手机号、短信验证码、密码和确认密码，调用 `/ios/auth/register/sms/send` 与 `/ios/auth/register`。
- H5 和 Android 继续显示并提交现有姓名、身份证、照片和紧急联系人字段，调用原注册接口。
- iOS 请求体不包含姓名、身份证、照片和紧急联系人字段。

### 确认订单与资料弹卡

`MallOrderCreateView.vue` 对三个平台都渲染现有 `components/order/create.vue`，因此商品卡片、地址、金额、订单限制、按钮和整体样式完全一致。

原商品 `salesMode` 继续决定购买方式：商城直付商品走原全款流程，先享后付商品走原先享后付流程。iOS 不新增支付方式选择页面。

iOS 用户点击原“提交订单”按钮时：

1. 先执行与原页面一致的登录、商品、地址、进行中订单、黑名单和额度检查。
2. 对先享后付商品读取 iOS 资料状态。
3. 资料不完整时，在当前确认订单页上方弹出资料填写卡片。
4. 已有完整资料时弹出脱敏资料确认卡片，可使用已有资料或重新填写。
5. 保存或确认后自动继续 iOS 风控与订单创建，不增加第二套订单页面。
6. 用户关闭弹卡时停留在确认订单页，不创建订单。

弹卡使用原商城的圆角、主题色、输入框和按钮风格。标题使用“完善申请资料”或“确认申请资料”；保留必要的隐私用途提示，但不出现开发、接口或风控实现描述。

### 个人中心与账号注销

`MallMyView.vue` 对三个平台都渲染现有 `MyCenterMobile.vue`。iOS 登录用户额外看到与原服务列表相同样式的“账号与安全”入口，点击后打开现有 iOS 注销确认卡片。H5 和 Android 不显示该入口，其他项目和布局不变。

注销页顶部使用与商城一致的白色圆角导航卡片、圆形返回图标和“账号与安全”标题。注销卡片只向用户说明“如您不再使用当前账号，可以申请注销”，不展示数据字段、存储方式、去标识化、法定期限或接口实现等内部说明；进行中业务的阻断原因继续使用用户可理解的订单状态文案。此次仅调整 iOS 页面展示，不修改注销接口和数据处理逻辑。

### 卡包、合同与通讯录

`MallCardPackageView.vue` 对三个平台都渲染现有 `MyCardPackageMobile.vue` 和 `CardPackageSection.vue`。

- H5 和 Android 继续使用现有卡包、合同和联系人处理分支。
- iOS 只在订单审核通过且用户进入合同签署前请求通讯录权限。
- iOS 上传调用 `/ios/orders/:orderId/contacts/upload/start`、`batch` 和 `complete`。
- iOS 上传系统实际授权返回的联系人，允许有限联系人授权；取消或拒绝时不上传并停留在当前卡包流程。
- iOS 提示使用商城用户文案，不推荐或诱导“完全访问”，不显示接口和审核实现说明。

## 平台隔离

平台差异只存在于共用组件中的小型守卫和独立 iOS API 模块：

- `isIosNativeApp() === false` 时，所有现有 H5 和 Android 分支保持原执行路径。
- `isIosNativeApp() === true` 时，注册、资料、先享后付建单、合同前联系人上传和账号注销使用 `/ios/*`。
- H5 和 Android 网络请求中不得出现 `/ios/*`。
- iOS 不调用原注册实名提交接口，也不为先享后付商品创建普通全款订单。

## 错误处理

- 资料状态读取失败：关闭加载状态，保留当前确认订单页并显示商城错误提示。
- 资料保存失败：弹卡保持打开，用户已填写内容不丢失。
- iOS 风控失败或中断：显示正常的订单审核结果提示，不创建订单。
- 通讯录取消或拒绝：不上传联系人，不进入合同签署，保留重试和返回路径。
- 账号注销被进行中业务阻断：显示服务端返回的用户可理解原因，不改变任何数据。

## 测试设计

先写会失败的源码契约测试，再实施修改：

- 四个入口不再渲染整套 iOS 页面组件。
- 注册共用 UI，iOS 字段与请求独立，H5 和 Android 原字段与接口保留。
- 订单页不存在 iOS “普通全款购买”选项和技术逻辑文案。
- 先享后付商品在 iOS 点击原提交按钮后才打开资料卡。
- iOS 资料完成后使用 `/ios/installment-*` 与 `/ios/installment/orders`；非 iOS 保留原流程。
- 个人中心和卡包使用原共用 UI，并只在 iOS 调用账号注销和联系人上传接口。

最终执行前端类型构建、后端测试、根目录乱码检查和 Git 空白错误检查。真机验收重点比较 iOS 与线上 H5 的注册外观、商品详情、确认订单、个人中心和卡包页面，并验证 iOS 唯一差异发生在资料收集与合同前通讯录授权节点。

## 回滚与上线

回滚只回滚前端代码，不执行数据库反向操作。后端已发布的加法式 `/ios/*` 接口保留，不影响 H5 和 Android。修复版本只通过新的 iOS 构建提交审核，不使用 OTA 或远程开关改变审核相关流程。
