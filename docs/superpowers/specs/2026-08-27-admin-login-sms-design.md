# 后台登录短信验证与取消 IP 白名单设计

## 目标

后台管理端不再依赖固定公网 IP 白名单。管理员使用账号和密码通过第一步校验后，系统向该后台账号在“账号管理”中绑定的手机号发送短信验证码；验证码通过后签发不可预测、可撤销、最长有效 12 小时的后台登录会话。会话有效期间不绑定 IP，也不重复发送验证码。

本次只调整后台管理端登录与鉴权，不修改商城用户登录，不迁移、不重置、不覆盖用户、订单、还款、地址、银行卡或支付数据。

## 已确认规则

- 验证码发送到当前后台账号 `adminAccounts.phone`，不发送给商城用户。
- 必须先校验账号和密码，校验成功后才允许发送验证码。
- 验证码通过后登录会话维持 12 小时，从验证成功时开始计算，不按凌晨零点统一失效。
- 12 小时内不重复验证，不限制登录后的 IP 变化。
- 主动退出、账号被禁用、会话被撤销或 12 小时到期后，必须重新进行账号密码和短信验证码验证。
- 不继续接受旧后台 `mock-token-手机号`、客户端角色请求头或查询参数作为后台身份凭据。
- 商城端现有 `mock-token-手机号` 暂不在本期修改，避免扩大业务影响范围。

## 推荐架构

采用服务端不透明会话，不采用仅签名且无法主动撤销的自包含令牌。

新增独立后台登录安全模块，职责分为：

1. 登录挑战服务：校验账号密码、账号状态和绑定手机号，生成六位验证码并发送短信。
2. 登录会话服务：验证码通过后生成随机会话令牌，服务端只保存令牌摘要。
3. 后台鉴权网关：识别后台专用令牌，检查会话状态、到期时间和账号状态，把可信账号写入请求上下文。
4. 后台路由目录：用服务端规则保护原 Nginx 白名单覆盖的管理接口，同时保留商城公开接口。
5. Nginx：只负责 HTTPS、静态文件和反向代理，不再按来源 IP 放行或拒绝后台访问。

## 登录流程

### 第一步：账号密码和发送验证码

后台登录页提交账号和密码到现有登录入口：

```text
POST /api/admin/login
POST /api/login（兼容入口）
```

服务端依次执行：

```text
定位后台账号
  -> 校验密码
  -> 校验 active 状态
  -> 校验租户访问范围
  -> 校验账号管理中绑定的 11 位手机号
  -> 创建登录挑战
  -> 发送短信验证码
```

成功响应不返回登录令牌，只返回：

- `challengeId`
- `phoneMasked`
- `expiresAt`
- `resendAt`
- `verificationRequired: true`

账号不存在、密码错误时返回统一错误，不暴露账号是否存在。手机号不合规或短信通道不可用时拒绝登录，不签发会话。

### 第二步：验证短信并签发会话

```text
POST /api/admin/login/verify
POST /api/login/verify（兼容入口）
```

请求包含 `challengeId` 和六位 `code`。验证成功后：

- 原子消费登录挑战，防止同一验证码被重复使用。
- 生成至少 32 字节的密码学安全随机令牌。
- 服务端只保存令牌的 HMAC-SHA256 摘要。
- 返回后台原有账号资料、权限信息、令牌和 `expiresAt`。
- 会话最长有效 12 小时，不因请求活动自动续期。

前端只在验证码验证成功后写入后台会话；旧本地会话没有有效的后台专用令牌时立即清除并返回登录页。

### 发送和校验限制

- 验证码使用 `crypto.randomInt()` 生成六位数字。
- 验证码有效期默认 5 分钟。
- 同一账号再次发送的最短间隔默认 60 秒。
- 同一账号、同一租户每小时默认最多发送 10 次。
- 同一验证码默认最多输错 5 次，达到后挑战失效。
- 验证码、会话令牌和管理员密码不得写入日志。
- 登录挑战和会话都不绑定 IP；IP 仅保留用于日志和问题排查。

## 后台会话与鉴权

后台会话令牌使用与商城令牌不同的固定版本前缀，后端据此区分两类身份。后台受保护接口必须先经过登录会话校验：

```text
Bearer 后台令牌
  -> 计算摘要
  -> 查询未撤销且未过期的会话
  -> 重新确认后台账号存在、状态为 active
  -> 确认账号仍可访问请求租户
  -> 将账号、角色和权限写入 ctx.state
  -> 执行现有权限和业务逻辑
```

以下旧兼容方式不得再为后台受保护接口授予身份：

- 可预测的 `mock-token-手机号`。
- `x-admin-phone`、`x-user-phone`。
- `x-admin-role`、`x-user-role`。
- 查询参数 `adminRole`。
- 未携带有效会话时默认超级管理员。

商城接口仍使用原商城鉴权路径。本次后台鉴权网关只覆盖现有后台访问目录，避免把商城登录、浏览商品、用户下单、支付回调和合作方接口误判为后台请求。

## 独立存储

新增两个独立 Mongo 集合，不加入现有 `store.js` 快照实体清单：

- `adminLoginChallenges`
- `adminLoginSessions`

登录挑战保存账号标识、租户、验证码摘要、发送和失败次数、状态、创建时间、到期时间、请求 IP 和 User-Agent。后台会话保存账号标识、租户、令牌摘要、创建时间、到期时间、撤销时间和创建 IP。

两个集合都使用 TTL 索引自动清理。集合中不保存验证码明文、会话令牌明文、管理员密码或业务数据快照。

## 前端登录页

登录页保持当前视觉风格，只把流程改为两个明确步骤：

1. 账号和密码。
2. 显示脱敏手机号、六位验证码输入框、发送倒计时和确认登录按钮。

验证码提交期间禁用按钮，防止重复请求。错误验证码只提示剩余可尝试次数或重新获取，不回显手机号明文。

后台会话增加 `expiresAt`。路由进入和 API 请求前发现会话过期时，清除本地会话并跳转登录页。接口返回 `401 ADMIN_LOGIN_SESSION_INVALID` 或 `401 ADMIN_LOGIN_SESSION_EXPIRED` 时执行相同行为。

## Nginx 变更

根目录 `nginx.conf` 修改为可整体替换的服务器配置：

- 删除 `geo $admin_ip_allowed`。
- 删除后台路由 IP 判断 `map`。
- 删除所有 `$admin_request_denied` 条件。
- 删除后台域名和 8080 中的三个 `allow` 与 `deny all`。
- 保留 `X-Real-IP $remote_addr`，用于服务端日志，不参与会话验证。
- `http://admin.wenshuosc.com` 继续跳转 HTTPS。
- 公网 8080 备用入口只跳转到 `https://admin.wenshuosc.com$request_uri`，不再通过 HTTP 接收后台账号、密码和验证码。
- 商城、API、静态资源、支付回调、合作方接口和流量后台的既有代理路径保持不变。

配置替换前先备份服务器现有 Nginx 文件，执行 `nginx -t` 成功后才允许 reload。

## 环境变量

所有可变参数分别写入开发、生产环境文件，并同步写入 `.env.example` 中文说明，不在代码中写死生产值：

```dotenv
ADMIN_LOGIN_SMS_MODE=enforce
ADMIN_LOGIN_SECURITY_SECRET=
ADMIN_LOGIN_SMS_MSG_TEMPLATE=
ADMIN_LOGIN_OTP_TTL_MS=300000
ADMIN_LOGIN_OTP_RESEND_MS=60000
ADMIN_LOGIN_OTP_HOURLY_SEND_LIMIT=10
ADMIN_LOGIN_OTP_MAX_ATTEMPTS=5
ADMIN_LOGIN_SESSION_TTL_MS=43200000
```

其中 `43200000` 为 12 小时。开发和生产必须使用不同的高强度密钥；短信模板必须包含 `{code}`，并使用短信平台已备案签名。

`enforce` 模式配置缺失、密钥无效或短信服务不可用时，后台登录失败关闭，不允许自动降级到密码单因素登录。

## 上线顺序

为避免先开放公网、后启用验证码造成安全空窗，部署顺序固定为：

1. 保持服务器现有 IP 白名单，先部署 API 和后台前端。
2. 在服务器 `.env.production` 配置后台登录短信变量和 12 小时会话，重启 API。
3. 从当前白名单 IP 完成一次账号密码、短信验证码、登录、退出和重新登录验证。
4. 检查所有需要登录的后台账号都已绑定有效手机号。
5. 确认后台受保护接口拒绝旧 `mock-token` 和伪造角色请求头。
6. 备份服务器 Nginx 配置，再用项目根目录的新 `nginx.conf` 替换。
7. 执行 `nginx -t`；只有成功后才执行 `systemctl reload nginx`。
8. 使用非白名单网络访问后台，完成短信登录和常用只读页面验证。

短信异常时恢复之前备份的 Nginx IP 白名单配置，不关闭后台短信鉴权，也不触碰业务数据。

## 测试与验收

后端自动化测试至少覆盖：

- 密码错误不发送短信。
- 禁用账号和无有效手机号账号不能创建挑战。
- 验证码只保存摘要且只能消费一次。
- 验证码过期、错误五次和发送限频正确拒绝。
- 验证成功签发随机后台令牌，服务端只保存摘要。
- 会话在 12 小时内有效，达到 12 小时后失效，不自动续期。
- 主动退出和账号禁用使会话失效。
- 会话不绑定 IP，换网后仍可使用。
- 旧后台 `mock-token`、手机号请求头、角色请求头和查询角色不能访问后台受保护接口。
- 商城公开接口、商城用户令牌、下单和支付路由不受后台鉴权网关影响。

前端自动化测试至少覆盖两步登录、脱敏手机号、倒计时、错误提示、12 小时过期清理和接口 401 清理会话。

Nginx 静态检查必须确认不存在旧 IP、`allow`、`deny all`、`admin_request_denied` 和 `admin_ip_allowed`，并确认 8080 只跳转 HTTPS。服务器部署前还必须通过真实 `nginx -t`。
