# 操作记录页面精简设计

## 目标

让老板和超级管理员按单个日期快速查看当天所有敏感操作，第一眼能够确认谁在什么时间操作了什么对象、修改了什么以及操作结果。

## 范围

- 仅修改后台管理端 `OperationLogsPage.vue` 和对应前端测试。
- 不修改后端接口、日志结构、权限、安全校验或业务数据。
- 保留现有日志详情抽屉和服务端分页。

## 页面结构

页面不再重复展示标题区，直接沿用后台顶部已有的“操作记录”页面标题。

主内容从上到下只包含：

1. 单行日期工具栏。
2. 操作记录表格。
3. 分页区域。
4. 点击“详情”后出现的右侧抽屉。

## 日期工具栏

- 只保留一个“操作日期”日期选择器，默认当天。
- 用户切换日期后自动重新查询，不设置“查询”和“重置”按钮。
- 工具栏右侧显示“当日共 X 条”，作为当前查询结果反馈。
- 删除类型、状态、操作人、关键词和 IP 筛选。
- 删除安全模式、绑定手机号和验证码就绪状态展示，也不再请求安全状态接口。

查询时将所选日期转换为本地当天 `00:00:00.000` 至 `23:59:59.999`，再以 ISO 时间传给现有日志列表接口。切换日期时页码重置为第一页。

## 表格

主表格保留以下关键信息：

| 列 | 内容 |
|---|---|
| 时间 | 当天时分秒，例如 `14:32:18` |
| 操作人 / 角色 | 姓名或账号，以及角色 |
| 操作类型 | 中文动作名称 |
| 操作对象 | 用户、脱敏手机号、订单号、期次 |
| 变更内容 | 人可读操作摘要 |
| IP | 可信客户端 IP |
| 结果 | 成功、失败、已拦截或处理中 |
| 操作 | 只读“详情”入口 |

验证方式不在主表展示，避免信息拥挤；仍在详情抽屉中显示。

分页默认每页 50 条，可切换 20、50、100 条。这里的“当天所有操作”指当天全部记录均可通过服务端分页访问，不把数量较大的结果一次性加载到浏览器。

## 详情抽屉

详情抽屉继续展示操作人、角色、完整时间、IP、验证方式、用户、订单、期次、操作编号、前后变化、摘要和失败原因。User-Agent 保留在详情中，不进入主表。

抽屉改为白色简洁信息布局，不再使用大面积红色渐变装饰；失败信息继续使用红色提醒。

## 视觉与响应式

- 使用现有后台的白色内容区、浅灰边框和红色强调色。
- 页面根容器使用不拉伸工具栏的纵向布局，消除截图中的大块空白。
- 日期工具栏保持紧凑，桌面端单行展示。
- 窄屏下日期和记录数量自然换行，表格横向滚动，详情抽屉全屏。
- 不增加统计卡片、图表、英文标识、动画或额外说明文案。

## 错误与空状态

- 日期查询失败时继续使用现有消息提示，不清空用户已选择的日期。
- 当天没有记录时显示“当日暂无操作记录”。
- 详情加载失败时保留当前行的基础信息并提示错误。

## 验证

- 前端源代码测试先验证单日选择、自动查询、精简字段和被移除元素。
- 运行安全功能前端测试。
- 运行后台生产构建。
- 从项目根目录运行中文乱码检查与 `git diff --check`。
